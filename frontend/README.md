# GoalPilot Frontend

GoalPilot 的 Vue 3 + Vite 前端，覆盖账户认证、目标持久化与“目标分析 → 信息澄清 → 计划生成”完整流程。

当前接入接口：

```text
POST /api/auth/register
POST /api/auth/login
GET  /api/auth/me
POST /api/goals
GET  /api/goals?page=1&size=9
GET  /api/goals/{goalId}
GET  /api/goals/{goalId}/active-plan
POST /api/goals/{goalId}/analyze
POST /api/goals/{goalId}/clarifications
POST /api/goals/{goalId}/assistant
POST /api/plans/generate
POST /api/plans/{planId}/approve
POST /api/plans/{planId}/reject
PATCH /api/tasks/{taskId}/status
```

登录成功后，前端会在本地保存 JWT，并为后续受保护请求自动添加 Bearer Token；
Token 失效或接口返回 `401` 时会清理会话并返回登录页。

用户提交新目标时，前端会先保存目标草稿，再进行 AI 分析。“我的目标”支持分页查看、
本页状态筛选与搜索、目标会话页以及继续分析已有目标。当前后端还未提供目标的编辑、删除和独立状态更新接口，
因此前端不模拟尚未存在的写入能力；详情中的空字段以精简的未记录提示展示。

已启用计划的目标可以在会话内展开正式计划，不会重新生成，也不会覆盖工作台未提交的内容。
正式计划读取区分暂无计划与其他读取失败，支持手动重试，同时读取目标状态以判断任务是否可操作。

### 目标助手

点击目标卡片的主体或「进入会话」，直接打开以对话为中心的目标页面，不再先弹出详情抽屉。
侧栏的最近目标也能直接切换会话。会话入口不限目标状态；尚无正式计划时也可以提问，但前端不会自动生成或启用计划。
助手仅查询和解释当前目标的正式计划、阶段、任务状态与完成标准，不修改计划或任务，也不读取未启用的草稿。

请求为 `POST /api/goals/{goalId}/assistant`，复用 Bearer Token，仅发送 `{ "message": "问题" }`，
读取 `{ "reply": "回答" }`。问题去除首尾空白后提交，输入最多 2000 字，空白问题不能发送。
后端不接收聊天历史或流式响应：每次问题独立处理，前端不发送历史记录、计划快照或用户 ID。
问答及未发送的问题按目标隔离，在本次登录的前端内存中保留；切换目标或打开工具面板不会丢失。
刷新页面或退出登录后清空，不伪造服务端聊天记录，也不把前端记录当作模型记忆。
离开目标时尚未完成的请求不继续写入本地会话，原问题保留，供返回后手动重试。

提问灵感只填入空输入框，不直接调用 AI，也不会覆盖已写的问题。等待回答期间锁定重复提交，
失败保留输入以便手动重试；不自动重发请求。`403/404` 提示目标不可访问并引导返回目标库；
`502` 作为助手暂不可用处理，不能推断成目标没有正式计划；空白或异常响应不展示为有效回答。
`401` 沿用登录失效处理，离开页面后忽略迟到的回答，避免不同目标之间串入内容。

回答通过文本插值展示，支持标题、分点、加粗及代码片段，不执行模型返回的 HTML 或链接。
回答旁的时间表示本机收到回答的时刻，不是计划保存时间。问答页支持键盘操作、移动端布局与减少动效。

### 任务进展与计划确认

目标和计划都为 `ACTIVE` 时，展开任务后可在「记录进展」中设置待开始、进行中、已完成或已跳过。
请求为 `PATCH /api/tasks/{taskId}/status`，请求体仅包含 `{ "status": "DONE" }` 等状态值，复用登录凭证。
四种状态可相互切换，已完成/已跳过的任务也可重新开始；选择当前状态不发请求。
草稿、未采用/已替代的计划，以及非进行中的目标不显示状态操作。

状态以服务器返回的任务为准，等待保存期间保持原完成数并锁定重复提交；不自行更新计划的保存时间。
工作台与目标库中的同一正式计划会同步成功返回的任务数据，不覆盖其他目标的未提交草稿。
当前阶段及任务展开状态在保存后保留；总进度仅统计 `DONE`，`SKIPPED` 单独提示，不计入已完成。
全部任务完成不自动把目标改为已完成，后端目前没有这项联动。

任务更新遇到 `409` / `404` / `403`、网络异常或无法确认的响应时，保留上次读取的状态并暂停写入，
通过「重新读取状态」同时核对目标与正式计划，不自动重试 PATCH；目标已停止进行时转为只读。
`400` 提示参数错误并允许重新选择，`401` 沿用登录失效处理。读取失败时仍保留计划供回看。

计划草稿支持「不采用这版」：二次确认后调用拒绝接口，成功返回 `204`（无响应体）。
前端随后将该版标记为未采用，保留目标、分析和当前会话中的路线内容；拒绝不会删除目标、
修改目标状态或自动重新生成。用户可以再手动生成新草稿，失败时仍保留上一版供回看与重试。
未采用的草稿不能再启用，正式计划也不提供拒绝入口。
同一会话返回目标库或详情时，尚在内存中的草稿提供「查看计划草稿」入口，避免重复生成；
该入口不等于刷新页面后的草稿恢复。

确认、拒绝或重新生成遇到 `409` / `404` 时，不猜测远端结果，不自动重试写入，
暂停旧版本的后续操作并提供前往目标库核对的入口。当前没有按计划 ID 读取草稿的接口，
因此冲突时无法直接恢复最新草稿内容；前端只查询已有的目标列表与正式计划接口。

澄清流程逐题填写并保留当前会话的回答，每轮问题全部答完后一起提交；当分析状态变为 `READY` 后，
页面会开放计划生成，并展示阶段、时间范围、任务说明和完成标准。

## 界面与交互

整体采用「目标会话为主、手动工具为辅」的组织：

- 新建目标是居中的自然语言输入区，补充条件按需展开；提交后进入目标会话。
- 已有的 AI 分析与澄清接口以对话形式呈现，问题在底部逐题回答，全部填写后一次提交。
- 计划草稿以可打开的结果卡片呈现，点击后在工具面板阅读、确认或拒绝。
- 自由问答区的输入框固定在会话底部，消息区域独立滚动；长问题不会挡住新回答的阅读起点。
- 「目标资料」「计划与任务」是会话内的辅助面板，大屏与对话并列，窄屏切换显示；关闭后回到对话。
- 侧栏保留最近目标，目标库负责搜索、筛选和归集，不再作为详情弹窗的入口。

路由为 `#/new`、`#/goals` 与 `#/goals/{goalId}`，支持浏览器前进、后退和直接打开目标。
刷新会重新校验目标并读取资料，但不会自动查询 AI、重新分析或生成计划。
目标读取失败时显示重试入口，迟到的读取结果不会切换当前目标。
当前规划流程的目标文字、澄清回答和草稿仍在内存中保留；开始规划另一个目标或刷新页面会重置该流程。
生成中的操作显示状态并锁定相关提交。所有确认、拒绝与任务更新仍调用原有接口，不用关键词匹配来伪装 Agent 写操作。

目标输入支持可选的完成时间、投入时间与成功标准，提交时合并为现有 `goalText` 字段，
总长度仍限制为 1000 字，不静默截断。输入区随文字适度增高，示例覆盖已有文字前需要确认。

目标收藏采用随数量铺开的卡片布局，状态通过柔和的分色与文字共同区分。
资料按目标描述、时间、成功标准及约束分组，长内容在面板内部滚动。
目标、分析、计划、任务的数据库 ID 仅用于内部接口请求，不展示为用户可见文案。
装饰复用透明底小纸飞机，配合 CSS 纸张、轨迹和星芒；无新增 UI 或动画依赖。
灵感卡片采用浅色便笺、非对称圆角与细线装饰，悬浮时轻微抬升；同类信息面板以底色和
柔和阴影分层，减少整圈描边，仍保留输入聚焦及键盘选中提示。页面不再展示 Enter 快捷提示。
计划操作独立成一个轻量选择面板，带小印章式线稿和展开动画；请求失败提示紧邻操作按钮，
确认面板展开后聚焦保留/取消按钮，减少误触。装饰为原生 SVG/CSS，不新增图片下载或动画依赖。

顶部保留中文日期和星期，窄屏让出更多空间给对话。
消息出现、工具面板、输入聚焦及筛选采用短过渡。计划采用「概览 → 阶段目录 → 当前阶段任务」
的阅读布局，去掉重复的状态统计栏；长思路按原文句子分点，完整内容可展开查看。
每个阶段默认展开第一项任务，其他说明按需展开，当前页面内切换阶段会保留各任务的展开状态。
大屏任务说明与完成标准并列，窄屏目录横向滑动，前后阶段按钮支持键盘焦点衔接。
保存/更新时间使用小日历、星期与独立时刻，分析与目标日期统一使用中文年月日；
日期组件同时提供紧凑样式，目标卡片仅显示日期，详情和分析页用小钟图标区分时刻。
年月、日期、时刻采用分级字重和等宽数字，辅助文字保持清晰对比，不新增字体或图片依赖。
日期缺失时显示未记录，不伪造保存时刻。日期字段不带时间时，也不会补出零点时间。
工具面板支持 Escape 关闭和焦点返回；计划确认中的 Escape 优先取消确认，不误关整个面板。
窄屏隐藏的对话设为 inert，避免键盘误入不可见内容。
系统启用「减少动态效果」时会关闭这些动效。

装饰资产见 [assets/README.md](src/assets/README.md)，为内置图片工具生成并压缩的 WebP。
远程字体采用非阻塞加载，字体服务不可用时使用本机无衬线字体。

界面回归检查可覆盖：创建与分析、返回后回答保留、失败重试、计划生成与确认、
阶段切换、任务展开记忆、目标筛选、工具面板键盘操作，以及 320–2560px 宽度的横向溢出检查。

## 启动

先按项目根目录 README 配置 MySQL、JWT 和 DeepSeek 并启动 `backend`（默认端口 `8080`），再执行：

```bash
npm install
npm run dev
```

浏览器访问 `http://localhost:5173`。开发服务器会把 `/api` 请求代理到
`http://localhost:8080`，因此本地开发不需要额外配置 CORS。

可通过环境变量覆盖后端地址：

```bash
VITE_API_BASE_URL=http://localhost:8080 npm run dev
```
